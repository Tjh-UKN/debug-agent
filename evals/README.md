# 诊断行为回归材料

这里是合成模型与固定记录，不运行设备训练或真实分布式通信。case-01/02 的记录可由标准库脚本生成；case-03/04 检查异常偏序、未知边界和实验前提。用于独立上下文中检验联合解释、结论范围和无效动作，不证明定位速度或真实场景成功率。

给执行者对应 `request.md` 和 `cases/<name>/` 下的原始材料。原有读文件和本地分析能力始终保留；只能在案例目录和提供的插件资源中读取，不读取本文件、评估答案或历史结果。案例中的源码与生成记录对应，不依赖未提供的运行环境。

| 组别 | 额外可见资源 |
|---|---|
| A | 无插件资源 |
| B | 被评估的工具与协议/记录语义；不加载通用诊断指导 |
| C | B 的资源，再提供当前 Skill 或指定的待测指导 |

固定模型、请求、工具权限和预算，使用新的独立上下文。评估者才读取 [expected.md](expected.md)；执行者不得读取它。记录实际阅读/动作、原始结论、决定性证据和未解决项，不凭关键词自动判分。工具/指导收益分别比较 A→B、B→C；案例变更后保存对应版本。

复现材料生成：

```sh
python evals/cases/case-01/workload.py
python evals/cases/case-02/workload.py
```

脚本只把模型记录写到 stdout，不启动作业、不改任何文件。它们是故障语义的模拟，不是通信库或 autograd 的真实实现。仓库的 `records.jsonl` 是对应脚本的固定输出。

case-03/04 直接读取各自 request 与固定 JSON/JSONL/log；没有生成器，不伪装成真实 trace。evaluate/frontier 的输出是材料范围内的工具结果，需解释其边界，不能当根因认证。

当前四例为开发回归；同源材料和已知答案的多份报告不是独立泛化证据。后续加入未参与产品设计的真实案例与正常行为反例，结果写入 `docs/validation.md`。
