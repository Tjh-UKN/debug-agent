# 运行时取证边界

按当前缺口选观察点，避免观测对象或采集方式使结论失效。

| 待核实对象 | 有用的证据 | 解释边界 |
|---|---|---|
| 实际运行实现 | 启动环境中的解释器、模块/动态库加载路径、配置与版本 | 源码修改、编译成功、安装成功和进程实际加载是不同事实 |
| 状态与对象复用 | 请求/对象 ID、进程/rank、分配与释放、生产和消费事件 | 地址或 block ID 会复用；不同 rank 的同号对象不是同一存储 |
| 异步依赖 | 提交、完成、访问边界与源码中的同步关系 | host 返回不等于设备完成；跨主机时钟不提供严格全序 |
| 状态被写坏 | 相同对象在可疑边界前后的值、身份和并发访问记录 | 差分证明变化，不单独证明写入者；最早观察到差异不必是起因 |
| 局部干预结果 | 实际生效的改动、保持的条件与结果变化 | 重启、同步或同时改变多项配置会影响归因；必要时恢复原行为作区分，不强制 A/B/A |

先确定缺少的字段与采集范围，再比较已有 trace、工具与局部 debug 代码。按目标版本核实工具能力；不存在固定的使用顺序。只采必要对象，保留较轻观察下的基线，插桩组与原始组分别解释。

张量转 CPU、dump、同步和重启可能改变时序。插桩要覆盖框架完成当前动作所需的后处理；某些图实现的 replay 提交后仍需参数更新，过早同步可能等待尚未提交的工作。以现场实现为准。

缩减可能联动序列长度、batch、并行切分、通信或缓存复用；核对与原问题的联系。原场景已有足够观察时不另构造实验；需估计偶发概率时先明确样本量/停止条件，不能靠反复未复现证明不存在。

保存必要命令、运行身份、配置、补丁与决定性输出；恢复时核实旧作业和产物再继续。已有日志可用[证据快照](evidence.md)固化。一次定位只做必要插桩，通用追踪平台须有独立需求。
