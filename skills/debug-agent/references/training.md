# 训练异常：选择有判别力的核查

用于不知道下一步该看哪个时间段、计算边界或证据类型时。先利用已有代码、日志和 dump；没有实验条件也可继续分析，不把采集工具或整套环境检查当作前置门槛。

## 先选能回答问题的窗口

| 当前事实 | 优先核查的对象 | 要区分什么 |
|---|---|---|
| 首个训练步的 loss 已不同 | 本次输入、初始权重、实际执行的前向路径；只查与差异相关的配置 | 差异已随输入进入，还是在当前计算内产生？同 seed 或同 checkpoint 名不证明实际输入/权重相同。 |
| 先前对齐，loss 在第 k 步才跳变 | k−1 步反向和参数更新、k 步权重及前向；已有哪段就先检查哪段 | 更新把差异带入了下一步，还是本步前向产生新差异？只比较 k 步输出可能漏掉起因。 |
| grad norm 先跳变 | 同步核对该指标与本步反向、归约后的参数梯度；需要时回查对应前向状态 | 异常在局部梯度、跨卡归约还是指标汇总中出现？不能将归约前后的量直接作上界比较。 |
| 异常步未知，全面 dump 成本高 | 已有趋势先定位时间段；可采集时优先轻量监控，再局部深入 | 首先缺的是异常窗口，还是具体算子证据？模块统计、API 统计、局部 tensor 分别服务于不同缺口，不必全量重采。 |

这些是选择窗口的线索，不是按序完成的清单。首个观测差异只给出可调查边界；用调用栈、输入输出对象和代码关系确认路径，不能把记录相邻当作数据依赖。

## 随机性与观测扰动

- **同 seed、跨设备结果不同**：先检查实际随机张量与数据顺序。随机数生成的实现可能不同；把“同 seed”当成“同输入”会误归因。可运行时，共用一份实际输入能区分输入差异与实现差异；关闭随机功能会改变场景，需确认原表现仍保留。
- **同设备重复运行不同**：核对输入及状态是否真正相同，再调查执行不确定性。已有 hash 可用于发现精确差异，但不同 hash 不给出误差大小，也不直接证明错误；摘要或 hash 比较仍需正确调用对应。
- **加 dump、同步或关闭 overlap 后异常消失**：这是观测/时序改变的线索。结合流依赖、buffer 生命周期和读写边界选择局部核查；现象消失不单独证明内存踩踏、硬件故障或问题已修复。保留原始场景，避免一次同时改变多个因素。

## 从可疑调用到可区分的原因

已有 msprobe 扫描时，用 [query](msprobe.md#复用扫描按问题查询) 同时查看各卡该调用的输入、输出统计及元数据差异，再用 compare/inspect 取完整字段与栈。若输入已不同，继续核查输入来源或敏感性；若当前证据只提示输出处差异增加，保留实现问题候选，核实参数、布局、dtype、实际路径与端口角色。没有原张量时不把输入摘要接近写成输入相等。

具备实验条件且现有证据仍不足时，可固定**同一份真实输入和参数**对照可疑实现与参考实现；随机生成的同 shape 输入不保证覆盖原触发条件。参考实现也需满足本次接口、dtype 和容差契约，CPU 或某个后端不自动是绝对真值。局部差异是否导致整网异常，还需代码证据或范围明确的干预联系起来。

提高精度、拆分融合、替换实现可以帮助判别，但要记录它们同时改变了哪些路径。大范围关闭功能后恢复正常只缩小相关范围；已有严谨静态证据链时，不为凑验证再运行实验。

频繁核查前考虑缩减：先明确需要保留的并行切分、通信组、输入形状或数值条件，再减少无关规模。每次以原表现是否保留判断有效性；不强求绝对最小，不将一个未复现的缩减场景当成对原因假设的反证。
