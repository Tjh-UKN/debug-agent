# 训练观察对象

需要解释 loss、NaN、grad norm、spike 或参数更新时查阅相关部分。以下是度量语义与可选观察对象，不是逐项检查表；使用已有材料能回答的问题，不另外采集。

| 当前未知 | 有判别力的观察对象 | 解释边界 |
|---|---|---|
| loss 变大是否代表计算异常 | 本次 batch/样本身份、loss 各项、实际 reduction 的分子与分母、mask/有效 token 数 | batch 构成、分母和跨卡汇总方式变化会改变指标；总 loss 不能直接定位算子错误 |
| 异常来自本步输入还是已有状态 | 本次输入、进入前向的权重/缓冲，以及上一步梯度与实际参数更新 | 相邻 step 的输入通常不同，不能将其输出直接当成同条件对照；仅在需要时恢复对应 checkpoint、数据和随机状态 |
| grad norm 的测量对象是否一致 | 对应参数集合、dtype、scale、累积阶段、归约/分片关系，以及记录处在 unscale/clip 的哪侧 | scaled norm、局部贡献、累积后梯度和裁剪后梯度是不同对象；norm 非有限也可能产生于范数计算，需关联原梯度 |
| 正常梯度是否在更新时被错误处理 | 同一参数更新前后值、optimizer 实际是否 step、学习率、相关 optimizer 状态、实际生效代码 | step 跳过、主权重与模型权重、原地共享存储须区分；更新量异常仍需由对应更新公式与状态解释 |
| NaN 首先在哪个已观测边界出现 | 同一对象进入/离开相关计算的有限状态、来源、调用栈和采集语义 | 首次观测不等于真正起点；msprobe 的 is_nan 是采集器报告状态，不是逐元素位置证明 |
| 异常步未知且完整 dump 成本高 | 已有趋势、轻量阶段记录，或当前相关模块/API 的局部记录 | 只收集能区分当前解释的范围，不将某种监控或全量 dump 设为前置条件 |

## 可适配的局部取证

当缺少现场事实时，可在实际代码已有的边界补观察。例如怀疑 loss 的归一化，记录当前已计算的分子、实际分母与有效 token 数；怀疑更新处理，记录相关参数在实际 step 前后的状态。示例只确定观察含义，具体位置和实现由现场代码决定。

记录需能关联同一作业、step/microstep、rank 与对象；字段以当前问题需要为准，不要求统一 schema。保存 tensor 的引用不是过去值的快照，后续原地更新会改变它；确需过去值时选择合适的复制/摘要方式，并估计内存与同步开销。不要在取证中额外调用 optimizer.step、unscale 或裁剪来制造观察边界。

在使用 GradScaler 的场景，检查或裁剪 `.grad` 时要明确是否已经 unscale；梯度累积期间的 scale 和 unscale 时点会影响语义。接口以实际安装版本为准，参见 [PyTorch AMP 示例](https://docs.pytorch.org/docs/stable/notes/amp_examples.html)。这份资料可用于解释度量，不要求每次运行 AMP 检查。

跨设备同 seed 不保证同一随机张量；dump、同步和 overlap 改动会影响时序；缩减卡数可能联动 batch、loss 分母、并行切分及通信。重放或缩减是否保留本次问题，需要实际材料支持。

msprobe 的协议和确定性读取见 [数据契约](msprobe.md)；统计与分片比较见 [数值证据语义](precision.md)。阈值、开关和修复方式由本次证据决定。
