# 精度实验的条件决策提示

只使用与当前证据相关的内容。这些领域提示的存在理由是：数值结果会同时受输入、指标、实现与执行条件影响，干预后“变好”可能有多个解释。

## 统计 dump 与执行证据

| 可见材料 | 可以支持什么 | 不能直接推出什么 / 下一步选择 |
|---|---|---|
| 部分 rank、样本或时间窗口的记录 | 该范围内的观察 | 不能称整个运行皆如此。要作整体排除时，先低成本汇总已有分区或验证外推条件；未读材料不是缺失材料 |
| Norm/Mean/Max/Min 相同或接近 | 所列统计量相同或接近 | 不能证明逐元素相同、逐元素增益相同或局部路径无异常；整体统计可能掩盖局部差异，缺少原张量时保留这个缺口 |
| dump 未记录某操作或写入 | 在当前采集范围未观测到 | 只有确认该操作会被采集、窗口覆盖且记录完整时，缺失才支持未执行 |
| 本地分片、完整梯度、扁平通信 bucket | 各自对应对象的统计 | shape 不同不证明无来源关系；先核查切分、拼接、归约和参数映射。已有全 rank 数据时，不用均匀分布假设替代实际全局指标 |
| 一份框架源码中的机制 | 该版本的一种可能执行路径 | 目标版本、实际路径与触发条件未确认前，不能写成本次运行事实；安装路径不同不等于版本不同 |
| 最早观测到差异与后续巨大数值 | 差异边界、传播或放大环节 | 不自动等于起因；区分异常起点、放大机制和最终症状，避免把其中任一点冒充完整因果链 |

msprobe 的执行序、栈关联、shape 对齐与全卡读取采用 [专门数据契约](msprobe.md) 及工具，不再临时编写相互不一致的读取器。其他结构化数据也应保留操作/字段来源和分片语义，不能把端口数差异当作实际计算差异。

先把用户所说的异常指标对应到材料中的实际记录，再选择有判别力的边界核查。统计扫描用于发现反例和缩小范围，不把“大数值最大的位置”直接当作根因。若局部反向量小但归约后梯度大，优先检查覆盖及测量对象能否比较；跨步残留等解释仍需自身触发条件的证据。

判断中保留必要条件：梯度为零不证明 detach；摘要相似不证明张量一致；EMA 摘要比例不唯一确定参数历史；调用名为 clip 不证明某个具体系数实际生效。数学上界也有对象与范围：不能将单卡、归约前的上界用作归约后分片的上界，或漏掉链中归一化/变形等算子的作用。未决因素可能共存，不因找到一个当前机制就排除所有伴随机制。

参数的构造或转换符合接口意图，不证明当前算子实现正确处理了它。区分“输入表达了什么”与“实际实现做了什么”；不能以整体输出差异不大作为语义错误必然不存在的依据，除非已证明该错误在当前输入下必然造成可观测的大差异。

数值小不自动等于噪声，也不证明没有真实任务梯度；“方向近似噪声”需额外证据。沿一条已确认对应的路径，将相邻非零范数比连乘得到端点比，是数量对账，不是触发原因的独立证据；没有路径对应时，连传播链也尚未建立。两端输出/输入范数比不同，也不能仅凭前向摘要接近就唯一归因于梯度分布差异。

## 实验与缩减

| 观察/缺口 | 有价值的候选核查 | 解释边界 |
|---|---|---|
| 两端数值不一致，比较口径未确认 | 输入、权重、样本/step/rank、layout、mask、dtype 与指标定义 | 数值更接近某端不自动证明该端正确；检查参考本身 |
| 特定路径、shape、dtype 才出现 | 结合代码核查分支、融合/编译路径、实际加载二进制 | 源码修改、编译、安装、运行加载是不同证据 |
| 怀疑低精度累加/误差放大 | 在相关计算边界做局部高精度或参考实现对照 | 提精度可能同时换内核或融合；记录连带变化，必要时拆分干预 |
| NaN/Inf 首次出现位置不清 | 优先从已知边界及代码缩小范围，再布置定点观测 | 最先观测到异常的位置可能只是传播节点；检查产生与传播的区别 |
| 只有大规模出现，需要多轮实验 | 保留可疑通信/切分/输入条件，尝试减少规模或运行路径 | 卡数变化可能联动全局 batch、并行拓扑、归约顺序、调度和实现选择 |
| 晚期迭代才出现 | 检查是否可从邻近 checkpoint 和相关状态复现 | 权重之外可能依赖优化器、随机数、数据游标及运行状态；按实际需要保存 |
| 偶发、复现概率不明 | 记录暴露条件、运行次数/时长及异常次数 | 重复预算由代价和原始频率决定，不固定复跑次数；零次观察不是不存在 |
| 开关/补丁消除了表现 | 核查干预范围与代码机制，选择足够的对照 | 广泛绕过只能缩小范围；针对性修复验证或完整证据链可闭环 |

缩减成功的判据是保留原问题表现，不要求先证明同一根因。若后来发现不属于同一问题，回退到仍有效的父场景并修订受影响结论。记录成功/未决/失败候选以避免重复尝试。

实验预算包括设备占用、排队、耗时、数据量和副作用。沿用用户授权和现有配额；只有真实缺少会改变决策的权限或资源时才询问，不额外制造审批流程。
