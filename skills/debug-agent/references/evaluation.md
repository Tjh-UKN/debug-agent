# 评估约定

本项目的存在价值是让同一模型更可靠、以更低成本完成定位。工具正确、记录完整和流程完成分别评价，不能代替诊断效果。

使用用户已定位的问题集时，参考答案与执行者材料隔离；保留当时实际可获得的代码、数据、权限和预算。已用于修缮的案例算回归，不当作未见案例。存档续跑明确预置事实与运行中人工参与，不计为从零发现。

| 评价对象 | 需要观察什么 |
|---|---|
| 问题定义 | 整体目标、已知/未知和各子问题边界是否清楚，是否把局部结论冒充整体完成。 |
| 问题选择 | 当前问题的答案是否改变候选范围或下一步；核查有没有减少重要未知、避免无效枚举。 |
| 证据与结果 | 结论是否有可复查依据，是否符合用户完成标准；错误闭环不能被方向命中抵消。 |
| 成本与接续 | 有效核查、重复工作、时间/设备/数据成本、人工介入，以及恢复后是否重复已完成工作。 |

固定模型、材料、工具权限和预算，分别比较：不加载项目、只用必要领域上下文与工具、使用完整 Skill。不同模型的效果单独比较。保留静态证据足够即可确认的正例，避免把“永不结案”误判为严谨。小节点检查不能替代完整案例，多次运行与未见案例用于检查稳定性。

每次修缮记录失败来源：确定性工具错误、协作状态缺口，或模型推断/规则执行问题。前两者用相应检查验证；后者依赖行为对照。切换模型后复查内容的存在理由，无可感知收益的补偿条款应精简或移除。

保留版本、输入与存档、实际操作、关键决策、原始交付、独立判定和成本记录；不为评估新建调度系统，也不向执行者补送预期答案。未做对照时，明确收益尚未证实。
