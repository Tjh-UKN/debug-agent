# 用真实案例验证决策能力

用户将提供已定位问题集。把初始可见材料与参考答案分开，评估 agent 只看到当时可获得的现象、代码、数据和权限条件；逐步提供实验反馈，避免答案泄漏。

对关键节点核查：

| 维度 | 可观察结果 |
|---|---|
| 假设形成 | 能追溯到事实/代码，预测可核查，不凭空罗列 |
| 下一步选择 | 针对实际判断缺口，能区分解释，考虑实验成本 |
| 缩减 | 在频繁昂贵实验时合理使用，保留表现，不追求绝对最小 |
| 证据解释 | 检查实验是否有效；区分未决、无效和反证；能据反证回溯 |
| 闭环 | 证据链或针对性修复验证足够，结论范围准确；不强求大场景 |
| 协作恢复 | 子任务可验收，状态与原始证据可追溯，无重复提交运行作业 |

记录实际实验次数、设备时间、墙钟时间、无效重复和数据采集量，结合结论正确性评价，不把“动作越多”视为越好。不要求与专家采取完全相同的路径；允许更便宜且同样有证据的替代决策。

对规则的保留/删除应有案例依据。模型升级后，在相同输入、工具、权限与预算条件下比较加载/不加载 Skill 的结果，关注真实改善及回归；删除已无价值的补偿规则。涉及随机结果时保留不确定性，不从单个成功样例宣称能力提升。

每个案例可用以下记录形式，由人工或现有评估平台维护，不新建调度系统：

```json
{
  "case": "真实问题的标识",
  "initial_materials": ["初始材料路径"],
  "reference_private": "评估者专用答案路径，不提供给执行 agent",
  "constraints": "工具、资源、时间和权限",
  "checkpoints": [
    {"observation": "当时可见事实", "decision": "实际选择", "evidence": ["记录路径"], "assessment": "判断依据"}
  ],
  "outcome": "结论与覆盖范围",
  "cost": "实际成本",
  "regressions": []
}
```
