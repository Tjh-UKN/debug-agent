# 问题驱动的实验与停止判定

用于长时间采集、受控复现、重放或有明确中途判据的动作。已有材料足够就直接分析；不是每次读文件都要建实验计划。本项目使用宿主运行能力，不提供独立调度器。

## 启动前确定有判别力的观察

围绕当前问题选择尽早能改变判断的信号，不要求预先存在根因假设。长动作应明确：问题与适用范围、有效前提、观察对象、回答条件、失效/预算条件、停止对象和产物保存方式。使用已有笔记或任务的 action/acceptance/run 即可；下面的结构化计划仅供确定性判定器使用。

局部重放要核实输入、权重/状态、实际实现与参考及触发条件；多项改动后的恢复不能直接分配因果。共享一次观察能减少重复实验，但不同问题仍需各自的判据和范围。轻量信号触发重采集之前，要考虑是否会错过短暂事件及插桩扰动。

## 运行中区分的结果

| 结果 | 意义 | 处理 |
|---|---|---|
| answered | 当前问题满足显式回答条件 | 保存证据，结束本轮动作，判断下一个问题 |
| refuted | 有效观察否定了一个明确命题 | 保留被否定命题及范围，不自动证明另一根因 |
| invalid | 当前实验必要前提被有效观察否定 | 原定推断不可使用，修正实验或换路 |
| inconclusive | 观察不足、冲突或缺少关键前提 | 保留未知；在允许范围继续或交付缺口 |
| budget | 预设预算到达 | 停止本轮；达到预算不是反证 |

“继续已无价值”是依据新证据重新选择动作的理由，不单独充当根因结论。局部重放回答了局部问题，原训练验证仍可能不可替代；不因一个实验给出支持证据就取消其他必要工作。

## 可复用判定器

`scripts/diagnosis.py evaluate --plan <plan.json> --events <events.jsonl> [--finished]` 只读现有事件并输出继续/停止建议；也可在现场采集循环中导入 `evaluate_experiment(plan, events, finished=False)`，在完整的相关事件边界重新计算。

计划示例：

```json
{
  "question":"同一输入与状态下，模块输出是否出现非有限值？",
  "context":{"run_id":"replay-42","window_id":"step8/rank0"},
  "preconditions":["same_input","same_state","reference_valid"],
  "rules":[{"id":"output_bad","when":{"output_nonfinite":true,"boundary_complete":true},"outcome":"answered","conclusion":"本次模块边界观察到非有限输出"}],
  "stop_target":"collection",
  "max_events":30
}
```

事件为独立 JSON 行，fact 是一次执行窗口内的命题，不是计数或随时间变化的信号：

```json
{"context":{"run_id":"replay-42","window_id":"step8/rank0"},"fact":"same_input","value":true,"validity":"valid","source":"input-check.log:3"}
```

- value 仅为 true/false/null；未知、无效或缺来源的记录不能满足判据。必要前提有有效 false 时 invalid；前提未知时，即使看见预期现象，也不能回答问题。
- 仅使用 context 完全对应的事件，其他运行/窗口保留忽略计数。跨 rank 的事实需以事实名和来源区分；窗口必须由实际身份与边界支持，不能用自报字符串冒充已核实。
- 同一事实的有效 true/false 冲突保留未知；不采用“最后一条覆盖前面”。不同结论的规则同时成立也保留冲突。更正或新一次执行应另立窗口、保留原始记录，再重新判断。
- `--finished` 仅声明本轮采集已结束；缺条件仍是 inconclusive。max_events 是匹配窗口的记录数预算，不是足以排除偶发故障的样本量。
- 判定器不核实用户声明是否真实、不证明因果、不连接设备，也不发送停止信号。输出 `process_stopped=false`；不得用它宣称真实作业已停止。

事件到达不是目标计算已完成。让规则依赖必要的完成/覆盖事实，并在该次观察足够完整时判定；不能把“看到 A”写成不检查前提的直接成功。随机故障需要适用的采样设计；反复查看固定样本检验并随意早停可能改变误判率，判定器不内置统计显著性或任意连续未复现判正常的规则。

## 实际停止与恢复

停止额外采集、结束受控实验和终止用户原作业分别处理。确定性局部断言可在已授权的复现循环内使用合作式退出；分布式参与方需按现场协议协调退出，不能只让某 rank 跳过后续 collective。

通过宿主结束真实实验前核实 run/job/PID 与启动身份及授权范围，使用现场支持的停止方式，保存决定性输出并检查真实退出/交接。停止成本、清理、重启代价也属于动作成本；用户要求保留原作业时不终止它。账本 cancelled 只是记录，不能代替停止核实。

问题回答、实验停止、可用规避、针对性修复与根因确认分别验收。将停止原因、已回答范围、未决条件及真实运行结果附在已有记录中；需要跨会话接续时使用[账本协议](tasks.md)，不另建状态系统。
