# 诊断展示协议

使用与 PUA 相近的交互形式：Unicode 方框、启动卡、进度卡、交付卡与 `▎` 旁白。内容围绕诊断事实，保持专业风格，不使用施压措辞、等级、绩效打分或虚构置信度。

按复杂度选择密度：短小核查用一句状态加结论；多步骤任务在开始、重要证据改变和交付时展示，不在每个工具调用前重复卡片。下面只是展示示例，不是要照着执行的固定步骤；示例数字不能作为当前事实。

## 启动

```text
DEBUG AGENT · 诊断启动
┌────────┬────────────────────────────────────┐
│ 问题   │ 训练中出现 NaN                     │
│ 目标   │ 定位原因                           │
│ 场景   │ 64 卡，保留原问题表现               │
│ 下一步 │ 核查异常分支与实际加载路径         │
└────────┴────────────────────────────────────┘
▎ 根据已有现象和代码选择核查，证据足够后收敛。
```

## 进度与判断更新

```text
DEBUG AGENT · 诊断进度
已知任务 █████░░░░░ 1/2（会随新证据调整，不代表定位完成度）
┌──────┬────────────────────┬──────────────┐
│ 任务 │ 核查问题           │ 状态         │
├──────┼────────────────────┼──────────────┤
│ T1   │ 缩减后是否仍复现   │ 已验收       │
│ T2   │ 修复点是否有效     │ 运行中       │
└──────┴────────────────────┴──────────────┘
▎ 新证据：小场景保留异常表现。下一步：在该场景验证具体修复。
```

进度条只能来自实际账本的 done/总任务数；取消项单独说明，没有任务时不生成百分比。任务验收包括有价值的阴性或未决结果，不代表假设被确认。原因假设用 open/supported/ruled_out/unresolved/confirmed 对应中文状态，不用模型自评百分比。

证据卡至少显示观察、来源和有效性。用户要求详细证据时保留命令、版本、实际加载路径与决定性日志链接，不将长日志全部挤进面板。

卡片内长文本可以省略显示，但结论、适用范围、限制以及证据观察必须在卡片下方补出完整文本，避免把重要限定条件裁掉。

## 交付

展示用户目标、当前结果、证据路线（证据链/针对性修复验证）、适用场景和保留限制。closed + blocked/narrowed 只能写“受阻待续/范围已缩小”，不能写“定位成功”。小场景已满足验收就可闭环，不因为未做大场景验证显示失败。

已持久化任务可用 `scripts/panel.py` 从账本生成卡片；该工具不触发实验、不更新状态。所有展示均应反映实际观察，不为填满卡片添加任务或制造自检。
