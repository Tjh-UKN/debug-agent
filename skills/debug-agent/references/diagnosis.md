# 证据、异常与定位操作

用于判据不清、跨层定位、多异常来源、范围细化或证据过多的场景。这里定义可组合的诊断结构，具体路径由现场决定；不要求建图、列全假设或登记账本。

## 信息与关联

S 是无需执行目标系统即可取得的代码、配置、规格、版本与历史资料；D 是实际执行产生的日志、张量、状态和轨迹。历史 dump 仍是 D，文件格式不决定分类。编译器本身是被调查对象时，其编译日志也是执行证据。来源类别不决定可信度；参考实现、规格、容差和正常基线提供判据，不能仅由“与对端不同”代替。

按当前问题建立局部关联：

| 关系 | 回答什么 | 必须保留的边界 |
|---|---|---|
| S-S 静态结构 | 谁调用、修改、配置或实现谁 | 代码中存在的路径未必本次实际执行；相似 Issue 是线索 |
| S-D 实际执行映射 | 本次事件运行了哪段实现、哪个分支和配置 | 修改、编译、安装与实际加载分开核实 |
| D-D 运行依赖 | 谁生产/消费同一对象，谁控制或等待谁 | 数据、控制、同步依赖分开；时间邻近和日志到达顺序不证明依赖 |

直接观测、依赖明确前提的推导、待验证关联分别表达。异常可来自输入、隐藏状态、组合关系或当前实现；下游暴露位置和首次数值超差都不自动成为根因。

## 判定：先明确什么算有问题

对待查对象明确运行/step/microstep/rank、阶段、测量对象及参考范围，再采用适用的判据。绝对不变量、参考差分、统计基线、跨节点关系约束可以并用；没有判据或条件不全就保留未知。

- **正常**：在有效上下文和声明覆盖内满足判据。
- **异常**：有效观察违反了明确判据，附具体见证。
- **未知**：参考、对象对应、关键条件、覆盖或观测不足；未知不能用于排除。

全局 Norm 正常不保证每个局部梯度正常；局部差异也不自动违反全局目标。有限输入可能携带已放大的误差，输入摘要相等不能排除未观测状态。NaN/Inf 是否违反约束须看字段语义，例如未初始化目的缓冲不能按计算结果判断。

`scripts/diagnosis.py judge --file <checks.json>` 可对已有标量或样本执行 finite/close/range 显式判据，输出三值判断。它不读取设备张量，也不为 loss、grad norm 或 dtype 自动选择阈值。输入中的上下文有效性与覆盖是调用方声明，不是工具验证的运行事实；完整格式与 CLI 参数见 `--help`。

```json
{"nodes":[{"id":"grad","source":"run42.log:18","scope":"run42/step8/rank0/unscaled-grad","context_valid":true,"coverage":"complete","check":{"kind":"close","actual":[1.01,2.0],"expected":[1.0,2.0],"atol":0.02,"rtol":0.0}}]}
```

## 偏序：保留首异常候选集合

在有依据的运行依赖图中，找没有已知异常祖先的异常节点，可得到当前已观测图中的极小异常集合。并发支路可能产生多个候选；单 rank 执行序、跨主机时间戳、API 编号都不足以给出全局异常总序。数据传播与等待关系还需结合现场解释。

`scripts/diagnosis.py frontier --file <graph.json>` 计算已提供依赖 DAG 的首异常候选，并保留未知祖先、未决关系和未判定节点。输入节点使用 normal/abnormal/unknown；每条边需要方向、关系类型、来源与 observed/derived/uncertain 依据。uncertain 边不用于排除候选。循环输入拒绝作为偏序，需区分执行实例或改用等待环分析。

```json
{"coverage":"partial","nodes":[{"id":"input","verdict":"unknown"},{"id":"op","verdict":"abnormal"},{"id":"loss","verdict":"abnormal"}],"edges":[{"from":"input","to":"op","kind":"data","basis":"observed","source":"trace:4"},{"from":"op","to":"loss","kind":"data","basis":"derived","source":"loaded-model.py:20"}]}
```

输出只给当前图中的候选，不认证全局首错或根因。已有 `trace.py` 的 investigates/parents 表达调查来源和结论必要前提，不能当成本工具的运行依赖边；msprobe alignment 也不直接提供这些边。

## 细化：缩小范围时保留机制

按当前缺口选择 step、microstep、rank、阶段、layer、module、op 或 kernel 维度；这些维度不是固定父子树。强证据可直接进入实现或代码，无需从全局指标逐层展开。

细化需要说明：新范围与已观察异常的关系、相关输入/输出与隐藏状态是否覆盖、边界外还有什么可能改变归因。子模块输出均符合各自约束，父模块组合仍可能出错；父指标正常也可能掩盖局部错误。没有安全剪枝依据时降优先级，保留回查边界。局部实验若改变并行切分、随机状态、缓存复用或执行时序，重新检查它与原故障的联系。

## 去噪与最小证据选择

优先折叠重复记录、聚合同一传播链并查询当前相关范围；保留原始来源、计数、过滤条件、缺失/未匹配及可恢复入口。小差异不是天然噪声，下游故障记录也可能提供依赖和触发边界。

降低材料优先级不等于排除相应根因。新证据冲突、前提失效或候选耗尽时，应重新检索先前折叠的材料并扩大范围。关键证据未知时，不能声称已保证关键证据召回率；去噪收益需用有参考答案的案例验收。

msprobe 已有 scan 时使用 query；`--focus differences` 仅折叠工具已完整比较且未见变化的记录，保留异常、差异、元数据变化、未知与未匹配项。折叠摘要相等不等于证明节点正常。

## 问题与动作选择

从当前证据找会改变判断或修复位置的关键未知；动作可以是读代码、核实际加载、查已有记录、补采、依赖追踪、细化、重放或验证。比较预期能回答什么、前提是否可满足、启动/采集/运行时间及扰动成本，不用工具调用量或“缩小了多少节点”代替进展。

根因假设有助于表达预测和区分性条件，但不是必选起点。缺失条件本身可以成为调查问题；证据充分时也可以直接得出结论。信息不足时说明具体缺口和可行的取证方式；没有可行方式则按该边界交付。遇到错误证据允许回退和扩大解释空间，不要求候选始终单调减少。

昂贵动作的有效前提、实时判据和早停方式见[实验判定](experiments.md)。整个问题的完成依据见[核心入口](../SKILL.md#完成边界)。
