# 产品定位与效果评估

Debug Agent 辅助模型定位 AI 训练/推理的运行失败与正确性问题。产品价值应体现为：同等条件下，正确归因更稳定，取得充分证据的时间和成本更低。模型选择路径；插件提供现场协议、可靠读取、可适配的取证手段与必要的恢复支持。具体经验是否值得保留，由诊断收益决定。

[诊断结构](diagnostic-architecture.md)将 S/D 关联、三值判定、异常偏序、保真细化、去噪、主动诊断和序贯停止组织为可组合能力。理论结构是否清楚、程序是否正确、指导是否提高定位收益分别评价；不因旧规则提及相似原则就视为能力已覆盖，也不因模型能够自己推导就预先否定结构化方法的价值。

## 保留和裁剪的标准

| 内容 | 处理 | 理由 |
|---|---|---|
| 目标、证据范围、完成边界和能力路由 | 放在短 SKILL.md | 说明交付契约与哪里有资料，路径由模型选择 |
| msprobe、产物快照、数值与运行时证据边界 | 按需保留并维护版本 | 确定性读取和取证减少误读；工具和环境事实也会过期 |
| 信息关联、判定/偏序/保真细化、去噪与实验停止 | 核心保留结构，细节与工具按需使用 | 说明操作语义和适用边界，不规定固定搜索路径；具体收益分别消融 |
| 训练度量、报错与挂死的观察语义、局部取证示例 | 按当前缺口读取 | 提供适用条件和解释边界，不把经验写成默认顺序 |
| 通用排查教程、模型补偿提醒和固定实验剧本 | 不默认加入；已有内容做消融 | 若模型已有能力，额外指导可能浪费成本或固定错误先验 |
| 状态、调查树、交接和更正传播 | 保留兼容，移出默认路径 | 跨会话与多节点确有用途；普通诊断不承担登记成本 |
| 启动卡、进度卡、固定旁白、同一原则的重复示例 | 删除要求、教程及 panel 渲染器 | 展示形式没有独立定位价值；状态复用已有 JSON 与自然语言交付 |
| 安装与产品评估 | 维护入口 | 不参与每次诊断；安装内容检查防止版本漂移 |
| 新平台、额外调度器和推理状态 schema | 不新增 | 已有宿主与工具足够，先验证真实缺口 |

源码审查、补观察、对照、缩减分别服务于当前缺口，不设固定步骤或工具升级顺序。案例用于开发验收，不自动生成执行模型必须遵守的剧本；答案与评分依据不进入 Skill 的加载路径。

## 怎样证明更稳定、更快

在独立上下文中比较三组：A 同模型用原有环境直接诊断；B 额外提供插件工具、协议与必要事实；C 在 B 的能力上额外提供被评估的经验指导。三组保留同样的执行约束与交付要求，比较时固定模型、材料、环境和预算。B/C 只改变待测插件资源或指导，不通过限制原有工具制造优势。参考答案只给评估者，执行中不补送预期结论。保存模型/配置、输入与插件版本、实际操作、原始交付与独立判定。

先以合成或历史案例查退化，再用未参与设计的真实案例；已用于修改本产品的案例只能作回归。公开静态小案例放在 [evals](../evals/README.md)，不随 Skill 安装，也不从运行入口引用。它们覆盖指标语义和 rank 执行分叉，可验证推断链与工具边界，不能证明真实设备任务提速。

实际覆盖需包括报错/异步错误暴露、挂死/数据等待、单端 loss/NaN/梯度异常、跨设备对应、状态偶发和材料不足；保留度量看似异常但计算正常的反例。初轮以少量重复试验寻找失败模式，不用一次答对、两个易例或短节点对照推广整体效果。

新增能力需覆盖：并发多个极小异常、未知上游与缺边、父指标正常而局部异常、子模块正常而组合错误、折叠材料中的关键反证、局部重放不能替代原故障验证，以及预期现象出现但实验前提无效。实验判定与真实停止分别记录；受控 CPU 循环通过不等于远程设备或分布式退出已验收。

| 指标 | 判定方式 |
|---|---|
| 正确根因或针对性修复 | 核对原始证据、机制与实际范围，不只匹配答案关键词 |
| 错误闭环 | 区分错误归因、局部结论冒充整体、缓解冒充修复和诚实未决；永不结案不算高质量 |
| 步骤有效性 | 重要动作是否依据可靠观察改变关键未知或纠正前提，而非只增加日志和工具调用 |
| 取得充分证据/最终交付时间 | 分开计量，同例配对看 P50/P90；保留失败与超时，不能只比较成功快例 |
| 设备成本、重复工作、人工介入 | 优先从运行记录取得；用量或时间拿不到时标缺失，不填 0 |
| 重复执行稳定性 | 比较原因归属与证据质量，不要求措辞一致 |
| 早停与证据选择 | 是否错误提前回答/取消必要工作、是否遗漏关键证据；保留停止后的必要验证及真实退出结果 |

先冻结验收条件：正确定位率不降低、错误闭环不增加，再评价成本是否稳定下降。分别评估 A→B 的取证收益和 B→C 的指导收益；如果 B 足够好，C 无稳定收益或使模型走偏，移除相应指导。确定性工具缺陷用回归测试处理，推断/决策失误用行为对照处理，不靠增加字段证明改进。

## 内容如何退役

模型升级时，优先对曾为模型短板添加的指导做有无对照；框架、采集协议或宿主升级时，优先核对接口事实和脚本。维护者在验证记录中说明被测内容的存在理由、适用版本和反例，无需让执行模型每次读这些记录，也不新增运行 schema。

- 不因内容具体就删除：若它说明模型无法推知的本次环境或记录语义，更新事实后仍可保留。
- 不因内容是专业经验就长期强制：只对部分场景有收益的材料保留为可选参考；无收益或诱发错误路径的指导归档或删除。
- 不因一次结果相同就判退役：检查相关失败模式、重复结果与成本；未取得足够样本时如实标为未决。
- 不以默认增加工具解决所有问题：已有工具可靠完成的动作不再封装；模型能稳定完成且更省的步骤可直接交给模型。

实际执行记录见 [validation.md](validation.md)。历史三组行为检查因账户用量限制未启动，无收益结论；新的公开回归与后续对照须单独记录。文档缩短、哈希一致和测试通过都不等于根因定位能力提升。
