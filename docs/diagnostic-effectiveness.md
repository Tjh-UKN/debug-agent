# 产品定位与效果评估

Debug Agent 是辅助模型定位 AI 正确性问题的 Skill。产品价值应体现为：同等条件下，正确归因更稳定，取得充分证据的时间和成本更低。代码分析、数据分析和实验选择由模型完成；产品提供数据契约、可靠取证工具与必要的恢复支持。

## 保留和裁剪的标准

| 内容 | 处理 | 理由 |
|---|---|---|
| 数据与代码联合分析、充分性、步骤有效性、收敛边界 | 集中到 SKILL.md | 直接约束诊断决策，避免多份说明反复教学 |
| msprobe、产物快照、数值与运行时证据边界 | 按需保留 | 确定性读取和取证减少误读、版本混用和手工抄录 |
| 状态、调查树、交接和更正传播 | 保留兼容，移出默认路径 | 跨会话与多节点确有用途；普通诊断不承担登记成本 |
| 启动卡、进度卡、固定旁白、同一原则的重复示例 | 删除要求与教程 | 展示形式没有独立定位价值；panel 接口仅供旧用户按需使用 |
| 安装与产品评估 | 维护入口 | 不参与每次诊断；安装内容检查防止版本漂移 |
| 新平台、额外调度器和推理状态 schema | 不新增 | 已有宿主与工具足够，先验证真实缺口 |

源码审查、补观察、对照、缩减分别服务于当前缺口，不设固定步骤或工具升级顺序。范围缩小不是唯一进展；修正错误前提也可能需要扩大范围。具体规则只有核心 Skill 一份，参考资料保留对象与工具特有约束。

## 怎样证明更稳定、更快

在独立上下文中比较三组：A 同模型直接诊断；B 仅必要领域资料与独立工具；C 当前 Skill 按需调用。固定材料、工具权限、环境和预算，参考答案只给评估者，执行中不补送预期结论。分别保存模型/配置、输入版本、实际操作、原始交付与独立判定。

先以合成或历史案例查退化，再用未参与设计的真实案例；已用于修改本产品的 KV 复读案例只能作回归。初轮可选 3–5 例、每组每例重复 2 次寻找失败模式，不据此推广总体收益。覆盖静态证据充分、版本/对象不匹配、数值对应、状态偶发和材料不足场景。

| 指标 | 判定方式 |
|---|---|
| 正确根因或针对性修复 | 核对原始证据、机制与实际范围，不只匹配答案关键词 |
| 错误闭环 | 区分错误归因、局部结论冒充整体、缓解冒充修复和诚实未决；永不结案不算高质量 |
| 步骤有效性 | 重要动作是否依据可靠观察改变关键未知或纠正前提，而非只增加日志和工具调用 |
| 取得充分证据/最终交付时间 | 分开计量，同例配对看 P50/P90；保留失败与超时，不能只比较成功快例 |
| 设备成本、重复工作、人工介入 | 优先从运行记录取得；用量或时间拿不到时标缺失，不填 0 |
| 重复执行稳定性 | 比较原因归属与证据质量，不要求措辞一致 |

先冻结验收条件：正确定位率不降低、错误闭环不增加，再评价成本是否稳定下降。若 B 与 C 质量相同且更省，就删掉没有收益的流程指导。确定性工具缺陷用回归测试处理，推断/决策失误用行为对照处理，不靠增加字段证明改进。

本轮只完成脚本、路由、安装与已有产物检查；三组行为检查因账户用量限制未启动，无收益结论。后续效果试验仍待执行，实际记录见 [validation.md](validation.md)。文档缩短、哈希一致和测试通过都不等于根因定位能力提升。
